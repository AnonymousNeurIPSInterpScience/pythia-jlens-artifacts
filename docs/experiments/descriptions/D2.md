# D2 -- device cross-validation of CUDA-scored against CPU-scored reads

## WHAT WAS RUN

Two files already on disk were joined: the `N=200` rung of each of the 15 `results/ladder410/*.json`
files, which were scored with `device = cuda`, and the matching `J|<corpus>|s<seed>` arm of
`results/e48_crossover_410m.json`, which was scored with `device = cpu`. Both scored the same
lenses (`results/e28_<corpus>_410m_n200_s<seed>.pt`) on the same band, the same k grid and the same
five admitted eval sets. For each of the 30 matched cells (5 corpora x 3 seeds x 2 aggregations) the
absolute and relative difference was recorded. No model was loaded, no fit performed and no rescoring
done.

## PRE-REGISTERED RULE (verbatim)

> DECISION RULE, fixed before looking.
>   AGREE      max |CUDA - CPU| < 1e-6 across all matched cells. The ladder's device is immaterial and
>              every ladder-derived number in the paper stands as reported.
>   DIVERGENT  max |CUDA - CPU| >= 1e-6. Report the magnitude and STOP. Every ladder-derived number
>              needs re-sourcing from a CPU scoring pass before it can be cited.
>   A tolerance of 1e-6 is the same one E52's C1 uses against e48, and is derived rather than tuned:
>   one (item, intermediate) pair flipping at one k moves a set mean by >= 1/(893*7) = 1.6e-4, so 1e-6
>   separates floating-point accumulation from a single changed decision.

Registration source: `experiments/d2_device_crossvalidation.py` module docstring, lines 20-28. The
results file stores the same derivation at `-> tolerance_derivation`:
